## 1. ASTRA 提示词系统核心量化哲学

在 ASTRA 系统中，大模型（LLM）的角色是**对冲基金交易台的“首席投资决策官（CIO）”**，而不是简单的问答机器人。

### 🎯 为什么提示词直接决定实盘盈亏？
量化交易的长期归宿由**单笔数学期望 $E$** 决定：
$$E = (\text{胜率} \times \text{平均盈利}) - (\text{败率} \times \text{平均亏损}) - \text{交易成本}$$

历史实盘复盘显示：**高胜率（如 60%）不等于能赚钱**。如果提示词在浮盈微小（如 +1%）时就惊慌失措地催促模型“保本平仓”或“提前落袋”，而在走势逆转时却留给止损 2.0x ATR 的宽大空间，系统就会陷入致命的**“赢小输大（盈亏比仅 0.45）”**恶性循环。

**优质提示词的核心使命**：
1. **顺应大势**：4H 多头大势专注回踩做多，4H 空头通道专注承压做空，震荡箱体边界高抛低吸；
2. **给足呼吸**：浮盈未稳固前严禁过早提损保本，拒绝在正常日内健康回抽中恐慌平仓；
3. **波段奔跑**：让有潜力的主升浪吃到 2.0R~3.0R 的深厚利润，用大单笔收益充分覆盖常规试错成本；
4. **敞口自律**：同向持仓达 2 笔以上时主动提升门禁，防范全市场单边系统性 Beta 踩踏。

## 2. 全量实时语义数据插槽权威字典 (Semantic Variables Reference)

ASTRA 提示词**全链路联动毫秒级真实实盘数据**。你可以在提示词中使用双花括号 `{{variable_name}}` 插入对应数据，系统在调用大模型前会自动完成变量渲染：

| 语义插槽占位符 | 中文名称 | 所属分类 | 注入的真实数据内容与实战用途 |
|---|---|---|---|
| `{{account_balance}}` | **账户可用资金** | 账户敞口 | 交易所私有接口实时拉取的可用 USDT 现金余额（如 `4393.08 USDT`），模型据此评估可用弹药。 |
| `{{risk_budget}}` | **自适应风控预算** | 账户敞口 | 根据可用余额与后台风控配置，现场推导的单笔保证金区间、单标的封顶、日亏熔断线、同向仓位上限、杠杆区间与 R:R 硬底线。**彻底杜绝模型臆造固定绝对金额。** |
| `{{account_positions}}` | **账户在管持仓** | 账户敞口 | 当前所有活动在手仓位：标的、方向、杠杆、均价、市价、浮盈 U、未结 ROI、**曾最高触及价（High Water Mark）与极值回撤百分比**、动态止损线。 |
| `{{pending_orders}}` | **在途未成交挂单** | 账户敞口 | 当前盘口挂单池中的 Maker 限价挂单 ID、标的、买卖方向、挂单价格、挂单数量与挂单时长，供模型执行 `KEEP` 或 `CANCEL`。 |
| `{{market_regime}}` | **全市场宏观体制**（★ 2026-10 **已退役·恒为空**） | 行情数理 | 原为全市场宏观体制自适应识别结果（趋势分/波动分/震荡指数/操盘建议），**已停止注入**：其数据源是已退役的数理引擎（`calculus_engine` → `calculus/regime.py`），且缺数据时会凭空编出体制结论与量化分（函数内写死 `atr_pct=1.5`/`adx=20.0` 兜底；实盘 `calculus` 块已完全不存在 ⇒ 震荡/冲击分源自**假零**），却以「当前全市场宏观体制为【X】｜主导方向=Y」的结论句进入提示词，且不在 P0–P3 证据分级内。方向证据改由每个标的的**真实** 4H 宏观结构、ADX、ATR 与 T4 动量承载。门禁：`tests/llm/test_brain_prompt_module.py::RetiredRegimeBlockIsGoneTests`。 |
| `{{market_matrix}}` | **全标的 7 梯队因子矩阵** | 因子证据 | **核心数据中枢**（2026-10 重构）：每个标的只注入**已加工的因子**，不再注入原始 K 线与数理噱头。七行对应七个梯队 —— T0 衍生品（费率/预测费率/费率拥挤度/OI/1H ΔOI/OI 四象限/散户与精英多空比/精英背离/清算脉冲）、T0.5 订单流（5M·1H CVD、Taker 买卖比、量价背离）、T1 盘口（OBI、Top5/Top20 深度比、有效点差）、T3 筹码（24H VWAP ±σ、VAH/VAL、VPVR POC）、T4 动量（1H MACD 柱/加速度/背离、1H·15M RSI 区间、ADX、ATR、布林带宽；MACD **同时给归一化「占现价 %」** —— 绝对柱值是价格单位的量，跨标的不可比）、T1.5 期权（ATM IV、25d 偏度、Put/Call OI 比）、T2 期限（季度基差年化、杠杆借贷利率）。**梯队缺失时只出一行明确说明，绝不用 0 或中性值冒充因子。** |
| `{{news_intelligence}}` | **全网实时资讯要闻** | 实时情报 | 金十数据与全网重大加密突发快讯流、美联储决议、宏观经济数据及系统判定的当前宏观情绪基调（偏多/偏空/震荡）。 |
| `{{trading_memory}}` | **自进化实战心法** | 自进化 | 系统根据历史已平仓真实台账，每日自动复盘沉淀的长效经验与避坑铁律（源自 `structured_trading_memory.json`）。 |
| `{{decision_timestamp}}` | **决策基准时间** | 系统环境 | 当前决策周期的精确北京时间戳（格式：`YYYY-MM-DD HH:MM:SS (北京时间)`）。 |
| `{{active_instruments}}` | **监控标的列表** | 系统环境 | 当前在管的加密货币交易对清单（**示例**：`BTC,ETH,SOL,XRP,DOGE,ARB`；实际以 `data/instrument_pool.json` 的标的池为准，池子可增删，提示词侧不写死名单）。 |

## 3. 破解“赢小输大”的五大提示词编写军规

如果你在编写自己的策略提示词，请务必贯彻以下五大实战铁律：

### ⚔️ 铁律一：科学波段呼吸，严禁过早提损保本
* **常见误区**：提示词写“浮盈一达到 1.0% 或 0.8R 立即移损到保本位”。
* **实盘恶果**：加密货币是高波动资产，15M 级别的正常回踩很容易产生 1% 的波动。过早保本会导致 70% 的潜力波段在刚启动时被白白扫出，只赚得几毛钱或者倒贴手续费。
* **正确写法**：
  > “持仓浮盈 < 1.0R~1.2R 坚持给足 1.8x~2.2x ATR 宽止损空间，留足结构呼吸时间；浮盈稳固达到 ≥ 1.5R 且波段形态确立后，方可输出 `UPDATE_SL` 将止损移至开仓成本 +0.20% 保本位。”

### ⚔️ 铁律二：杜绝惊慌市价砸盘，让主升浪波段奔跑
* **常见误区**：提示词写“只要浮盈较最高点回撤 30% 无论如何立刻市价全平”。
* **实盘恶果**：一笔单子刚浮盈 3U，盘面出现一次微幅拉回 1U，模型就惊恐执行 `CLOSE_MARKET`。盈利单被死死压制在 2~5U，而止损单却一亏就是 20U。
* **正确写法**：
  > “严禁在轻度浮盈（< 1.5R）的日内正常回踩中恐慌性市价平仓；只有当持仓曾录得显著深厚利润（浮盈 ≥ 1.8R~2.0R）且 1H 动能出现明确结构性破位时，才启动主动锁利退出。”

### ⚔️ 铁律三：多资产同向敞口自律，防范系统性 Beta 踩踏
* **常见误区**：提示词没有同向约束，在 BTC、ETH、SOL、SUI 上同时满仓做多或做空。
* **实盘恶果**：大盘一旦出现插针或单边异动，所有标的连环触发止损，单日亏损瞬间击穿心理防线。
* **正确写法**：
  > “全账户同向在手仓位达到 2 笔以上时，新开同向单必须自律提升开仓置信度门槛至 85% 以上，且严禁在高相关标的上无节制堆叠单边敞口，防范系统性 Beta 踩踏。”

### ⚔️ 铁律四：止损出局后坚决冷静，杜绝绞肉市连续接刀
* **常见误区**：模型在同一标的被止损后，下一周期看到 1H 稍微企稳立刻再次同向开仓。
* **实盘恶果**：在震荡绞肉市中（如典型的 ARB 假突破行情），单一币种在 24 小时内连开 6 次连续止损，账户被同一把钝刀反复磨损。
* **正确写法**：
  > “标的一旦触发止损离场，必须严格遵守风险预算声明的冷静期；冷静期内或该标的未出现明确突破大级别结构前，坚决保持 WAIT，杜绝急躁反手与情绪化连续抄底摸顶。”

### ⚔️ 铁律五：入场遵循 Maker 限价挂单，严守后台配置的盈亏比硬底线
* **核心规范**：
  - 做多几何：`stop_loss_price < entry_price < take_profit_price`
  - 做空几何：`take_profit_price < entry_price < stop_loss_price`
  - 严禁市价追单，挂单锚定在盘口支撑/阻力位附近（现价下方/上方 0.1%~0.6%）；
  - 止损距离参考 1.8x~2.2x 1H ATR，止盈距离不得低于后台风控页声明的盈亏比硬底线
    （`ASTRA_MIN_RISK_REWARD`，**当前 1.6**；2026-10 由 2.0 下调，高置信度动态正期望可再放行至 1.2 绝对底线）。

## 4. 提示词策略管线与四大分层结构

在系统的「提示词工坊」中，提示词被解耦为四大核心管线（Pipelines），你可以针对性进行增量模块定制：

```text
┌─────────────────────────────────────────────────────────────┐
│                    ASTRA 提示词工程管线结构                    │
├──────────────────────────────┬──────────────────────────────┤
│ 1. trading_system (系统主宪法)│ 设定模型角色、快节奏兑现纪律与铁律 │
├──────────────────────────────┼──────────────────────────────┤
│ 2. trading_user (用户推演上下文)│ 注入真实市场矩阵、持仓与推演任务 │
├──────────────────────────────┼──────────────────────────────┤
│ 3. evolution_system (复盘系统)│ 设定自进化认知中枢的复盘反思规则 │
├──────────────────────────────┼──────────────────────────────┤
│ 4. evolution_user (复盘上下文) │ 注入真实已平仓台账流水与心法库  │
└──────────────────────────────┴──────────────────────────────┘
```

### 4.1 事实源：正文**只存 JSON**（2026-09-30 重构）

> ⚡ **这是本指南最重要的一条**：提示词的**全部正文**只存在
> `data/prompt_library.json`（出厂基线，git 跟踪）与
> `data/prompt_library.local.json`（用户改动），由提示词工坊编辑。
> Python 源码里**不再有**任何提示词正文 —— 唯一的例外是下面那个只读契约。

重构前，同一段文案存在**三份**副本（`SYSTEM_PROMPT` / `EVOLUTION_SYSTEM_PROMPT` /
`PRESETS`），加上工坊编辑的第四份；改一处另几处不动，表现就是
**「在工坊里改了、实发却没变」**。现在收敛为一方。

| 角色 | 归属 | 可否编辑 |
|---|---|---|
| **输出 JSON Schema**（`严格 JSON 规范契约与完整输出骨架`）| **代码**（`scripts/ai_brain_trader.py::READONLY_OUTPUT_SCHEMA`）| ❌ **只读**：工坊里不可改、不可删、不可禁用；`validate_profile` 会 fail-closed 拒绝 |
| 其余全部正文（角色/军规/节奏/形态/任务/复盘规则）| `data/prompt_library.json` 的 `source:"custom"` 模块 | ✅ 工坊自由编辑 |
| **实时数据** | 代码逐周期生成（`runtime_vars`），经 `{{slot}}` 注入 | — |

**为什么 Schema 必须只读**：它是模型输出的**机器契约**，字段名与取值枚举必须与
`scripts/brain/dispatch.py` 的解析器**逐字对齐**。改一个字段名就可能让整轮决策解析失败
（实测一次「字符串里一个裸换行」就足以打掉一个交易周期）。故它归代码所有。
若确实需要调整输出契约：**改代码 → 发版**，而不是在工坊里改。

> 🔒 即使有人绕过界面直接调 API 删除它，渲染边界
> （`normalize_base_modules`）也会按规范顺序把它**回插**回实发提示词 ——
> 「删掉 ≠ 生效」，这是刻意设计的 fail-safe。

### 4.2 模块来源（`source`）

| 来源 | 含义 |
|---|---|
| `base` | 代码基座：内容恒取代码。**现在只剩只读 Schema 一条**（且 `locked=true`）。 |
| `custom` | 用户/方案自有模块。四条管线的**业务正文全在这一类**。 |
| `legacy` | 覆盖层：曾被标为 `base` 但内容与代码基座不同（历史遗留或改写降级），按自己的正文发出。 |

**另外三条管线刻意没有代码基座**（`base_template_text()` 返回空串）：正文 100% 来自
JSON，不再存在「代码基座覆盖存档」这条静默路径。

## 5. 出厂实战模板与经典范例 (Battle-Tested Templates)

### 模板一：快节奏·高胜率主策略（`trading_system` 出厂范本）

> 本节的文字**与 `data/prompt_library.json` 的出厂基线同源**；改文案请改 JSON
> （工坊里就能改），不要改这里 —— 文档不参与实发。

```markdown
======================= 【首席交易官定位与快节奏高胜率总纲】 =======================
你是 AstraQuant 的首席 AI 交易官（CIO），负责 1H~4H 加密合约多空双向的实盘裁决。

▍三个 KPI 的优先级（本策略的立身之本）：
1. 胜率优先：先把「能赢的单」做成常态，再谈单笔赔率。宁可少做，绝不可乱做；
2. 资金周转优先：机会必须在可预期时间内兑现，不允许把资金压在横盘里等故事；
3. 单笔赔率第三：赔率是结果而不是目标 —— 为了追超高赔率而死等远端目标，
   正是「坐电梯」与「赢小输大」的主要来源。

▍快节奏的可执行口径：
- 每笔持仓都要能在执行层的时间止损阈值内给出结果：要么达到兑现条件，要么主动离场；
- 止损出局后，冷静期一过立即重新评估候选池，不因上一单亏损而畏手畏脚；
- 空仓不是仓位，是待命状态：没有达标形态就 WAIT，但也不允许因怕亏而放掉已达标的机会。

▍高胜率的定义：
- 只在「证据链最短、失效位最近」的机会上下注；
- 入场必须「看得见确认」，而不是「猜得中未来」；
- 亏损靠及早认错截断，而不是指望别打到止损。

======================= 【快节奏兑现与亏损截断（本策略的核心纪律）】 =======================
▍一、默认兑现路径＝分批止盈（先落袋，再谈奔跑）
执行层已配置自动化分批止盈：底仓浮盈达到【本周期风险预算】声明的分批门槛时，
会自动市价平掉一部分并同步提损保本。把它当作首选兑现路径，优先取结构可达的近端目标。

▍二、失效即离场（截断亏损 —— 直接决定盈亏比结构）
一旦开仓理由消失，不要等硬止损，立即输出 CLOSE_MARKET：
- 结构失效位被有效击穿（收盘价站到失效位之外）；
- 1H 动能由顺转逆（速度与加速度同向反转）；
- 量能／主力资金明确反向，原入场逻辑不再成立。
目标：把单笔实现亏损控制在 1R 量级，绝不允许小错拖成大错。

▍三、时间止损（快节奏的硬约束）
持仓时间超过【本周期风险预算】声明的时间止损阈值仍未达 +1R ⇒ 主动减仓或 CLOSE_MARKET。

▍四、止损后的冷静期：冷静期内不得再申请该标的，冷静期一过立即重新评估。

▍五、移动止盈阶梯（与执行层同源）：达保本门槛 ⇒ UPDATE_SL 移至保本；
   达锁利门槛 ⇒ UPDATE_SL 锁定成本上方至少 +1.0R；峰值大幅回撤且 1H 破位 ⇒ CLOSE_MARKET。
```

> 📌 **口径同源铁律**：上述文案里的所有阈值都是**文案描述**，真正的硬阈值由
> `scripts/risk_constants.py`（后台风控页写入 `.env`）确定，并由每轮用户消息的
> 【本周期风险预算】小节**实时声明**。提示词口径与执行层口径必须一致 ——
> 否则模型会按不存在的空间规划下单。

### 模板二：多模型投委会席位模板 (Council Roster Templates)

#### 席位 A：资深交易员 A (顺势波段型 `trader_trend`)

### ⚠️ 白盒安全护栏审查规则 (`scan_forbidden`)
为了保护账户资产物理安全，系统在保存、导入或应用任何提示词模板时，都会经过内建的代码级白盒安全审查。**以下表述组合会触发系统安全拦截，请务必避免**：

   - ❌ 错误示例：*“你可以忽略 P0 约束”、“跳过止损检查”、“覆盖执行层门禁”*；
   - ✅ 正确表述：*“在 P0 硬约束框架内严格执行”、“严格对齐风险预算声明”*。
